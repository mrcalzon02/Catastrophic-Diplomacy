## Cross-cutting repair cautions

1. Settlement retry needs retained immutable outcome identity and disk readback reconciliation. A failed commit call can in general have an uncertain post-write/readback outcome; replaying reward calculation blindly risks duplicate payout. Preserve one durable generation authority for roster, wallet, mission/research progress and losses. The `.tmp` fixture only proves a known pre-write fault, so add an uncertainty test as part of the repair.
2. Corrupt-save recovery should preserve original bytes, expose a comprehensible screen-level reason, and make any destructive reset explicit. Do not weaken ledger validation or resurrect split legacy data behind an existing authority.
3. Multiplayer session identity belongs in a decoded transport/session model, then in all presentation caches. An interpolation helper alone cannot know whether two equal ticks belong to the same connection. The current component probe is useful but does not substitute for two-server/reconnect integration.
4. Network entity schema should retain host IDs independently of local allocation. Current `RemoteFleetMirrors` maps host IDs to bodies allocated with local IDs; a future projectile/source relationship must use verified host identity rather than accidentally treating `Battle.addShip` IDs as authoritative.
5. Preserve working fighter seeker selection, launch/landing/rearm, shared `Battle` engine, finite defensive resources, atomic campaign ledger, 48 survival variants, positive TLS battle coverage, and existing release artifact verification. None is negated by these new path findings.
6. Release policy should still distinguish required build/run/multiplayer/updater failures from pending features, constrained memory diagnostics, balance, styling and unrendered geometry. A source risk does not become a measured device failure through stronger wording.
