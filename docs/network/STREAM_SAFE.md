# Stream Safe — implemented boundaries and remaining acceptance

Stream Safe is a persistent local presentation preference. It does not alter admission, roles, saves, simulation or security warnings. It defaults on. Saved labels and local friend labels become consistent session pseudonyms; endpoints, ports, passwords, keys, cards and pins remain masked even with Stream Safe off. Reveal controls are not offered by this slice. Swing controls disable IME composition/copy access and use password accessibility; native entries draw only masks, never a final-character peek. Private copy requires an explicit warning/confirmation and does not auto-copy on host start. Stream Safe can be changed while management views are open.

Beckenburg lobby arbitrary text is hidden in safe mode and its existing log clears on toggle; in-world nameplates are pseudonymized and chat text is hidden. Malefic native JOIN fields and network errors are neutral, and raw menu update text is omitted from application logs. Dedicated startup no longer prints endpoints/data paths. The new protocol's toString methods conceal endpoint/identity/contact details and no password appears on argv. Randomized Swing presentation tests check label/list text, password echo/accessibility and existing-widget OFF→ON toggles.

This is **not comprehensive capture acceptance**. Native GPU keyboard/paste/IME behavior, loading/pause/reconnect transitions, every pre-existing diagnostic/crash/screenshot/console/overlay path and external capture have not all been inspected. World/campaign naming and other pre-existing screens may still disclose private labels. Do not claim a stream-safe release until the full handoff sentinel/capture matrix passes. The OS keyboard, clipboard history, screen readers, administrator access, other apps and spoken secrets are outside these app-only protections. Direct peers and the network path still see connection endpoints; Stream Safe does not make direct-IP play anonymous.
