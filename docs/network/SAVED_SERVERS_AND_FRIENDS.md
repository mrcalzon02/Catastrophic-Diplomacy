# Saved servers and local friends

Use the existing multiplayer area: Beckenburg's embedded Saved Servers & Friends tab; Malefic's native JOIN → Saved Servers / Friends (software fallback also has an embedded connection tab); Catastrophic's MULTIPLAYER entry. Endpoints, ports, passwords, pins and friend cards are masked from their first character. Enter an ASCII DNS A-label, IPv4, or bracketed/unbracketed host-only IPv6 and a separate integer port. URLs, user-info, spaces in addresses, controls/Unicode and invalid ports are rejected. Passwords preserve spaces and support printable ASCII 12–128 on TLS. There is no public search or background ping; no fake status or latency is shown.

Verify a server certificate fingerprint privately before saving/connecting. A changed pin blocks an edit/reconnect until the user deliberately removes and verifies the entry again. A signed invitation validates package integrity but does not establish the sender's trustworthiness: verify the sender/fingerprint out of band. Invitation import never runs a URL or downloads content, and never includes the room password. LAN discovery, observed refresh, full recent-server tracking and one-use invitation capabilities remain unfinished.

Exchange the complete HBFRIEND1 public card privately. A checksum detects altered card text; successful authenticated challenge-response, not the nickname or checksum, proves possession. New cards enter pending review; local acceptance alone grants no server privilege. Block/unblock/removal/favorites/labels persist locally. Presence stays unknown unless a direct authenticated observation is actually recorded. Imported contact backups exclude private keys, endpoints and verified-key/ACL authority; imported new contacts require review. There is no global friend polling, account lookup or contact-graph upload. Active authenticated friend requests, reviewed host-ACL import, device identity migration/re-key flows, server-side invitation revocation and complete native contact backup/export UI remain gates.
