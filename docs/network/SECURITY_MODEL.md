The implementation uses Java 17 JSSE TLS 1.3 and explicit exact certificate pinning before application credentials. It never trusts an unknown/changed certificate automatically, and never reconnects over plaintext after TLS failure. New handshakes carry HBNET/version/game ID and bounded length-prefixed ASCII frames. P-256 signatures cover fresh 256-bit server nonces and the game/public key. The password verifier uses a fresh 128-bit salt and PBKDF2-HMAC-SHA256 (210,000 iterations, 256-bit output); generated room keys contain 160 random bits. Passwords are 12–128 printable ASCII characters, spaces preserved. Buffers are cleared when feasible; legacy String-based game APIs and Java heap copies are not guaranteed erasable.

The enclosing game hosts additionally cap connections and queues. These are bounded prototype protections, not demonstrated Internet DoS resistance or complete per-identity policy/ban safeguards. Ghost/hunter role secrecy, original game permission checks, reconnect token rotation and save rules remain authoritative. Secure Beckenburg has no UDP socket; voice is explicitly disabled, so there is no plaintext media downgrade.
