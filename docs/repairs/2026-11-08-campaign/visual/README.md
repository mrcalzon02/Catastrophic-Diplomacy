# Actual recovery screen captures

These images come from the production `CatastrophicGame` / `GameMenuPanel` renderer under a real LWJGL3 OpenGL context. They are not mockups or screenshot edits. The runner uses freshly compiled core/game/desktop classes, verified release 693 resources and external libraries, and isolated temporary save directories.

## Reproduce

1. Compile the current source with Java 17: `:core:classes :game:classes :desktop:compileJava`.
2. Copy `run_capture.py` and `RecoveryVisualCapture.java` into a temporary capture directory so historical screenshots remain intact. Run `python /path/to/capture/run_capture.py --repo /path/to/Catastrophic-Diplomacy --audit /path/to/audit-work`. The audit-work directory supplies the verified release resources/external JAR classpath, Temurin 17.0.21+9 and Xvfb used in the original audit; its setup is described in the [audit evidence](../../../audits/2026-11-08/README.md). The script defaults preserve the original execution paths; portable reruns should pass both arguments.
3. Read `capture-manifest.json` and both `capture-*.log` files. The runner rejects source newer than its compiled class and snapshots the current classes before launch.

The runner launches Xvfb and Java in the same Python process, using TCP display 127.0.0.1:94 because Unix display sockets are unavailable here. OpenGL runs on Mesa llvmpipe. No emulator, release dispatch, installation, publication or user save is involved. Audio is disabled for this visual check.

## Controlled real-controller sequence

- Start the actual game and create a valid isolated campaign ledger with four commissioned vessels.
- Populate a controlled finished battle with three survivors, one destroyed vessel and distinct spent stores. The report is generated by the actual after-action model; this is not a naturally played match.
- Create a directory at the ledger `.tmp` path, invoke actual `finishEngagement`, and capture the pending-save Results framebuffer.
- Remove the fault and invoke the actual registered R keyboard handler. It routes through the Results primary action, commits generation 2 exactly once and leaves the saved report visible for capture.
- Damage both isolated authorities, invoke actual restore/setup and the registered Enter handler. Capture the first-press confirmation before replacement.
- Invoke the actual Escape handler and assert the corrupt files are preserved and the game returns HOME.

## Viewports and limits

1280×720 is the desktop capture. 1560×720 is a 19.5:9 landscape phone-aspect viewport using the same desktop renderer; it is not Android or physical-device acceptance. Both capture all four real report rows. Images are raw vertically corrected OpenGL framebuffer PNGs written by LibGDX, without subsequent editing.
